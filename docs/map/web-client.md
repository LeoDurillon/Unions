# Map: `apps/web/client`

Generated by `bun run map` from each file's top comment (else its first documented
export); do not edit. Tests are left out.

## ./

- `app.tsx`: The root layout of the web app: sidebar, main area, ticket panel, dialogs and the project wizard.
- `main.tsx`: The browser entry point: mounts the React app with its query client.

## components/agents/

- `agent-card.tsx`: One agent's prompt, model, effort and tools, saved to the database; the next run of that step uses them.
- `agent-labels.ts`: The titles and descriptions the agents page shows for each agent, model and effort level.
- `agents-page.tsx`: The agents page: a card per agent, plus the lists of tools and MCP connectors.
- `connector-list.tsx`: The claude.ai connectors the agents can use (Figma…), read from the Claude account the worker runs agents with.
- `effort-field.tsx`: How hard the agent thinks (`claude --effort`); Default leaves it to Claude Code.
- `model-field.tsx`: The Claude model an agent runs with.
- `tool-list.tsx`: The tools the user added to the list, and the form to add more.
- `tools-field.tsx`: Multi-select over the tool list: each tool is a toggle; the selection keeps the list's order.

- `log-tab.tsx`: Replays the ticket's whole agent log, then follows it live.

- `notion-import.tsx`: Fetches a page of the project's Notion data source, previews it, and creates the ticket.

- `refused-commit.tsx`: Shown on the step paused on a refused commit: the changes, the hook's output, the decision.

- `ui.tsx`: One line: a pill wrapped over two lines reads as a blob; too long, it ends in an ellipsis.

## components/investigations/

## components/notifications/

## lib/

- `agent-events.ts`: Condenses one raw `claude -p` stream-json event into zero or more log lines.
- `agent-review-api.ts`: `base` is the review's API root (`reviewBase`).
- `answers.ts`: The intake step ends its questions with an `Answer:` line for the user to fill in.
- `api.ts`: What a GitHub call is made with: a token, or an installation of the stored GitHub App.
- `attachments-api.ts`: Why the file cannot be attached, checked before sending it; null when it can.
- `choice-values.ts`: A multi-select rule value is its option names joined by commas (Notion option names cannot hold one); the worker splits it the same way.
- `desktop-notifications.ts`: Desktop notifications: off until the user turns them on, shown by the one tab that holds the event stream.
- `diff-selection.ts`: A click starts a selection; a shift-click on the same side extends it to a block.
- `env-lines.ts`: `KEY=value` lines (blank lines and `#` comments skipped) to variables.
- `event-hub.ts`: Calls `listener` with every new event, in any tab's stream; returns the unsubscribe.
- `event-rules-api.ts`: The browser's client for the event rules endpoints.
- `file-tree.ts`: The files as a directory tree, for the review's file list.
- `github-markdown.ts`: Renders GitHub comment text as GitHub does: its HTML (folds, images) sanitized, and `> [!NOTE]` alerts.
- `highlight.ts`: Tokens for every changed or context line of a patch.
- `investigate-ticket.ts`: Opens Investigations with a new investigation on the ticket ready to write (`?investigate=<id>`).
- `labels.ts`: The step the ticket is currently on, if any.
- `leave-guard.ts`: Unsaved settings: the forms holding changes, and asking before a navigation throws them away.
- `line-diff.ts`: The lines of `after` against `before`: kept, added or removed, in reading order.
- `log-runs.ts`: Splits the log at each run header, so every run can fold on its own.
- `notifications-api.ts`: The browser's client for the notifications: a page of them, and marking them read.
- `open-notification.ts`: Opens what a notification is about (its ticket or investigation, in its project) and marks it read.
- `opened-investigation.ts`: The investigation opened from elsewhere (a notification), in the URL (`?investigation=<id>`).
- `pr-description-api.ts`: The browser's client for a ticket's pull request description endpoints.
- `preview-api.ts`: The browser's client for a ticket's preview endpoints.
- `project-files-api.ts`: The browser's client for a project's uploaded files.
- `refused-commit-api.ts`: The ticket's last refused commit, or null.
- `review-grouping-api.ts`: `base` is the review's API root (`reviewBase`).
- `review-target.ts`: Where the target's diff, comments and send live; also the root of its query keys.
- `settings-sections.ts`: The project settings page open in the URL (`?settings=preview-services`), or null.
- `spec-hunks.ts`: The hunks of `path` that serve the part; null when the file serves it whole, or the part is unknown.
- `split-rows.ts`: Pairs a patch's lines for side-by-side display: a context line faces itself, and each run of removed lines faces the added lines that follow it, row by row; th…
- `url-state.ts`: Sets or removes (`null`) query parameters as one history entry, and tells every reader.
- `use-active-project.ts`: The project list plus the remembered selection, falling back to the first project.
- `use-agent-review.ts`: The latest agent review of the target, with starting and cancelling it.
- `use-agent-tools.ts`: The tools agents pick from: built-in ones and the ones the user added.
- `use-app-state.ts`: What the root layout runs on: live refetching, the projects, the open ticket, navigation, and opening notifications.
- `use-commits.ts`: The change's commits, oldest first, and (tickets) the change since the last review.
- `use-connectors.ts`: The account's claude.ai connectors, and reading them again (polled while the worker checks).
- `use-container-runs.ts`: The commands run in the ticket's workspace (polled while one is on), and running or stopping one.
- `use-current-reviews.ts`: Adding and removing refresh the list (and the Pull requests tab, which marks what is in it).
- `use-event-stream.ts`: Calls `onEvent` with every new event, from the browser's one shared stream (`event-hub.ts`).
- `use-github-app.ts`: The global GitHub App's status; saving or removing it invalidates `['github-app']`.
- `use-live-invalidation.ts`: Refetches board, ticket, investigation and notification data whenever the worker records a change.
- `use-log.ts`: Polls a ticket's or an investigation's Log while it is shown: all of it first, then what is new.
- `use-navigation.ts`: Which page is shown and which overlay is open; `show`/`goTo` return click handlers.
- `use-notifications.ts`: The notifications, page by page, with the unread count (also in the tab's title) and marking them read.
- `use-notion-users.ts`: The Notion workspace members, read only when `enabled` (a person property is in view).
- `use-review-grouping.ts`: The newest grouping by spec of the review, with starting and cancelling one.
- `use-review.ts`: A pull request under review: its description and discussion, read from GitHub once per opening.
- `use-selected-ticket.ts`: The open ticket lives in the URL (`?ticket=3`), so it survives reloads and back/forward.
- `use-settings-form.ts`: A settings page's form: what is edited, whether it differs from what was saved, and its one Save.
- `use-stored-number.ts`: A number remembered in localStorage; storage being unavailable only loses the memory.
- `use-ticket-commands.ts`: The hook that sends commands for a ticket and refreshes what the page shows afterwards.
- `verdict.ts`: The reviewer's verdict line (`VERDICT: APPROVED` / `VERDICT: CHANGES_REQUESTED`), if any.
