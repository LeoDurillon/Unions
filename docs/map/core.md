## ./

- `agent-environment.ts`: The agent's environment settings as sent (`agentVariables`, `forwardPorts`), checked; only what differs from the defaults is kept.
- `agent-log.ts`: Writes the agents' output to `agent_log`, and reads a Log: events and agent lines in one order.
- `agent-reviews.ts`: Fails the reviews a stopped worker left running, and returns them.
- `agent-tools.ts`: A tool the list refuses: bad syntax, duplicate, built-in, or still selected by an agent.
- `agents.ts`: The agents' default prompts, models, efforts and tools, the user's overrides, and how a run resolves them.
- `attachment-limits.ts`: Upload limits, shared by the server and the browser (which checks them before sending).
- `attachments.ts`: Where the agents find a ticket's files: next to the repository, so `git add -A` never sees them.
- `container-runs.ts`: The ticket's latest runs, newest first.
- `db.ts`: Fresh handle, never cached: tests use `createDb(':memory:')`.
- `diff-excerpt.ts`: The text of `start..end` on one side of a file's patch; null when none of those lines is in it.
- `diff-hunks.ts`: A file's patch as hunks: the grouping by spec places hunks, the review page shows some of them.
- `diff.ts`: Unified diff parsing (output of `git diff`).
- `docker-cli.ts`: The container runtime that drives the `docker` command line to run ticket containers.
- `e2e-screenshots.ts`: Replaces the ticket's e2e screenshots with `files` (none: just removes them).
- `event-actions.ts`: The kinds of event rule action and what each holds; browser-safe, for the settings page and the worker.
- `event-catalog.ts`: The event log's types: a typed event to write, and a guard that narrows an event read back.
- `event-cursors.ts`: Readers that follow the event log (the rule deliveries, the notifications) and how far each got.
- `event-deliveries.ts`: Reads the events logged since the last call and queues one delivery per matching enabled rule of the ticket's project.
- `event-notion-action.ts`: The Notion action of a rule: the properties it sets, checked against the stored Notion columns, and what it sends.
- `event-payloads.ts`: What each type of event in the log carries, keyed by its `type`: the one place to add an event.
- `event-rule-types.ts`: Event rules: when something happens to a ticket, do something elsewhere.
- `event-rules.ts`: Event rules: checking and saving them, the stored Notion columns, and matching events and templates.
- `github-auth.ts`: A project's installation wins over its token; `fallbackToken` (the `GITHUB_TOKEN` environment variable) covers projects with neither.

- `index.ts`: The package's public API: re-exports every core module.
- `investigation-defaults.ts`: What a new investigation runs with until the user picks otherwise.
- `investigation-tickets.ts`: Asks for a ticket written from an answered investigation, with what the user wants it to cover.
- `investigations.ts`: Newest first.
- `mcp-connectors.ts`: The permission rule for all of a connector's tools.
- `notifications.ts`: Which events of the log notify the user, and with what text; pure, the worker writes the rows.
- `notion-api.ts`: A column of a data source: its id (stable across renames), name, type, and choices if any.
- `notion-error.ts`: A Notion failure with the HTTP status to answer with (401 bad token, 404 not shared).
- `notion-id.ts`: A whole ID: not touching other hex characters, so slugs like `Add-feed-<id>` cannot shift it.
- `notion-markdown.ts`: Notion's page markdown (`GET /v1/pages/{id}/markdown`) as plain GitHub-flavored markdown: its own tags (mentions, callouts, colored or commented spans, toggles…
