## ./

- `active-work.ts`: The work in progress a restart interrupts, per table: `bun run active` and the Update dialog list it.
- `agent-environment.ts`: The agent's environment settings as sent (`agentVariables`, `forwardPorts`, `startForImplementation`), checked; only what differs from the defaults is kept.
- `agent-inputs.ts`: What the user gave the implementer's next run: command outputs and CI outputs, read together and marked read together.
- `agent-log.ts`: Writes the agents' output to `agent_log`, and reads a Log: events and agent lines in one order.
- `agent-review-specs.ts`: The specifications an agent review is given: read from the request, and written into the agent's prompt.
- `agent-reviews.ts`: The reviews a stack run covers, bottom first; empty for a run on one change.
- `agent-tools.ts`: A tool the list refuses: bad syntax, duplicate, built-in, or still selected by an agent.
- `agent-usage-record.ts`: Records an agent call's usage from its `result` line in `agent_log`, live or replayed from the past.
- `agent-usage-totals.ts`: What a ticket's or an investigation's agent calls used, per run and per call, summed for the Usage tables.
- `agent-usage.ts`: Reads what a `claude -p` call consumed from its stream-json events: tokens per model, and its peak context.
- `agents.ts`: The agents' default prompts, models, efforts and tools, the user's overrides, and how a run resolves them.
- `ansi.ts`: Strips terminal colour codes from command and CI output; browser-safe.
- `attachment-limits.ts`: Upload limits, shared by the server and the browser (which checks them before sending).
- `attachments.ts`: Where the agents find a ticket's files: next to the repository, so `git add -A` never sees them.
- `ci-output-text.ts`: The text the implementer gets from CI: a failed check (its failed step's log, annotations, summary), another job's log, a bot's comment; browser-safe.
- `ci-outputs.ts`: CI output given to the implementer: kept for its next run, or sent now as a revision with the user's note.
- `container-init.ts`: Identifies this container's run: its init's (PID 1) start in clock ticks, which a container restart changes and a `bun --watch` reload does not.
- `container-runs.ts`: The owner's latest runs, newest first.
- `custom-agent-config.ts`: A custom agent's defaults (its written prompt, Sonnet, the review tools) and what its settings page shows of it.
- `custom-agent-usage.ts`: What still runs a custom agent: project flow presets that name it, and tickets not yet done whose flow has it.
- `custom-agents.ts`: Custom agents: created and edited by the web, their prompts written by the worker's prompt writer, deleted softly.
- `db.ts`: Fresh handle, never cached: tests use `createDb(':memory:')`.
- `diagrams.ts`: How agents draw diagrams in their answers: Mermaid code blocks, which Union and GitHub both render.
- `diff-excerpt.ts`: The text of `start..end` on one side of a file's patch; null when none of those lines is in it.
- `diff-hunks.ts`: A file's patch as hunks: the grouping by spec places hunks, the review page shows some of them.
- `diff.ts`: Unified diff parsing (output of `git diff`).

- `event-actions.ts`: The kinds of event rule action and what each holds; browser-safe, for the settings page and the worker.

- `event-cursors.ts`: Readers that follow the event log (the rule deliveries, the notifications) and how far each got.
