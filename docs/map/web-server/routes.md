# Map: `apps/web/src/routes/`

The API routes by resource: projects and their settings, the events stream, agents, attachments, integrations, investigations, memory, notifications, previews, repository, setup, usage, Union settings and update.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `agent-image.ts`: `/api/projects/:projectId/agent-image`: the image the project's agents run on, a new one saved, or the save dropped.
- `agents.ts`: The API routes for agents: their instructions, models, efforts, tools and connectors.
- `api.ts`: Every `/api` route, with the outside services they may call.
- `attachments.ts`: `/api/tickets/:id/attachments`: a ticket's files, checked against the limits and stored on the host.
- `claude-usage.ts`: The API routes for Claude usage: how much of the subscription's windows is used, what a project's agents used.
- `container-runs.ts`: `/api/tickets/:id/container-runs`: commands the user runs in the ticket's workspace, with the end of their output.
- `custom-agents.ts`: The API routes for custom agents: create one of a kind, rename it, rewrite its role, regenerate, delete.
- `event-rules.ts`: `/api/projects/:projectId/event-rules` and its deliveries, and the stored Notion columns and Jira fields.
- `events.ts`: The API route that streams new events to the browser as server-sent events.
- `github-app.ts`: The global GitHub App: its credentials are checked against GitHub before they are stored.
- `github-errors.ts`: Turns GitHub failures into messages the wizard can show next to the field.
- `github-imports.ts`: `/api/tickets/github-issue` and `/api/tickets/github-pull-request`: tickets imported from the project's repository.
- `github-project-link.ts`: `/api/projects/:projectId/github-project`: the GitHub Projects the board can mirror to, and connecting one.
- `github.ts`: The wizard's GitHub reads; each request carries a `token` or an app `installationId`.
- `guide.ts`: The user guide, read-only: the pages of `documentation/` and the screenshots they show.
- `integrations.ts`: Connecting a project to a tracker, reading its columns again, importing one of its items, hiding some of its fields.
- `investigations.ts`: `/api/projects/:projectId/investigations`: one agent run on the user's prompt, with no GitHub issue.
- `issue-import.ts`: `/api/tickets/github-issue`: a ticket from an existing issue of the project's repository.
- `jira-picks.ts`: `GET /api/projects/:projectId/jira/picks/:type`: what a Jira field rule can pick, read from Jira when the editor asks.
- `live.ts`: The routes no project owns: the event stream, the notifications it announces, the running previews, Union's update.
- `mcp-connectors.ts`: `/api/agents/connectors`: the account's claude.ai connectors as last read, and `POST /check` to read them again.
- `memory.ts`: `/api/projects/:projectId/lessons`, `/feedback`, `/lesson-suggestion` and `/lesson-tidy`: the project's memory.
- `notifications.ts`: `/api/notifications`: what needs the user across every project, marking them read and clearing them.
- `preview-reset.ts`: A preview's reset as the routes queue it: refused when it cannot happen now.
- `preview-settings-parts.ts`: The parts of the preview settings that core checks: the agent's environment, the shared services' commands.
- `preview-settings.ts`: `/api/projects/:projectId/preview`: how the project's tickets run as previews, and its secret variables.
- `preview-subject.ts`: What a preview's routes share for a ticket and for a pull request under review: the view, the refusals, the commands.
- `preview.ts`: `/api/tickets/:id/preview`: the ticket's preview and the commands that start, stop, reset and read it.
- `project-files.ts`: `/api/projects/:projectId/files`: the files every ticket's workspace gets; the browser never sees their content.
- `project-flows.ts`: The flow presets part of a project settings change, refused with a 400 when they do not hold.
- `project-github.ts`: Project GitHub routes with their own module: what an event rule picks from, the Repository tab, its GitHub Project.
- `project-settings.ts`: Updates a project's settings, or deletes the project (GitHub is left untouched).
- `project-size.ts`: The project's size settings: the paths left out of a change's lines of code.
- `project-subroutes.ts`: The routes under `/api/projects` that have their own module.
- `projects.ts`: The API routes for projects: creating, reading and updating them.
- `refused-commit.ts`: The ticket's last refused commit (null if none): what the user decides on while the run is paused.
- `repository.ts`: `/api/projects/:projectId/repository`: the Repository tab's reads from GitHub (commit, tree, file, branches).
- `rule-choices.ts`: What a rule picks from on GitHub, read live: the repo's labels and users, the Project's fields.
- `run-input.ts`: A command run as the user asks for it, for a ticket's workspace or a pull request's: the body read, checked and queued.
- `run-progress.ts`: The API route for the board's live progress: what each running agent of a project is doing now.
- `running-previews.ts`: `/api/previews`: every preview holding containers, whatever its project, and stopping one (the worker does).
- `setup.ts`: `/api/projects/:projectId/setup`: the setup agent's latest run and its proposal, and queuing a new run.
- `shared-services.ts`: `/api/projects/:projectId/shared-services`: the project's shared services as the worker last saw them, who uses them.
- `spec-sources.ts`: A specification's text from where the user points: the PR, the ticket, a GitHub issue, a tracker's item.
- `tracker-comments.ts`: `/api/tickets/:id/trackers/:kind/comments`: the comments of the ticket's tracker item, read now through its adapter.
- `tracker-errors.ts`: The trackers' failures as HTTP answers: a refusal, a value or item refused, the tracker's own status.
- `tracker-fields.ts`: `/api/tickets/:id/tracker-fields`: sets one property of the ticket's Notion page or Jira issue; the worker sends it.
- `tracker-item.ts`: `GET /api/tickets/:id/trackers/:kind/item`: the ticket's tracker item for its tab's card, read now.
- `union-settings.ts`: `/api/union-settings`: Union's machine settings, the memory (in whole GB) and the CPU cores its containers may use.
- `union-update.ts`: `/api/union-update`: how far Union's checkout is behind `origin/main`, and commands to check again and update.
- `usage.ts`: `/api/tickets/:id/usage`: what the ticket's agent calls used, per run, written by the worker as each call ends.
- `workspace-settings.ts`: The project settings of what a ticket's workspace runs with: its preview, its files and its agents' image.
