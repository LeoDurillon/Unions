# Map: `apps/web/src/routes/review/`

Review routes: current reviews, diff, comments, explanations, groupings, reports, runs, specs, trackers, preview, import and removal.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `agent-review.ts`: A review's agent review: the latest one, starting it (queued for the worker) and cancelling it.
- `closed-reviews.ts`: Pull requests under review that a read from GitHub shows closed or merged: removed with what they hold.
- `current-review-list.ts`: The pull requests under review of a project as the Pull requests tab lists them, without their files.
- `current-reviews.ts`: `/api/projects/:projectId/pull-requests/reviews`: pull requests the user reviews without a ticket.
- `explanation-request.ts`: Reads a request to explain lines of the diff, or to follow up on an explanation, into what is queued.
- `file-flags.ts`: What the review marks on each changed file: ignored by the review's rules, and code by the change size's.
- `grouping-targets.ts`: The grouping, explanation, spec, report and review agent routes, under a ticket and under a pull request under review.
- `review-agent-runs.ts`: Review agent routes under a review's base: `/review-agents`, `POST /review-agents`, `/review-agents/:runId/cancel`.
- `review-comments.ts`: Review comments of a ticket or of a pull request under review: drafts, edits, outdated marks and sending.
- `review-diff.ts`: A ticket's newest diff for the review page: its snapshot, its files with flags, and whether a review can be sent now.
- `review-explanations.ts`: The explanations of a review's lines: listed with their spec parts, queued, cancelled, and their progress.
- `review-groupings.ts`: Grouping routes under a review's base: `/groupings`, `/groupings/source`, `POST /groupings`, `/groupings/cancel`.
- `review-import.ts`: The PR tab's routes: the discussion, and importing its threads and notes as draft comments.
- `review-jira.ts`: `<review>/jira`: the Jira issues a pull request under review is linked to (its `jira` specs), and those it names.
- `review-notion-suggestions.ts`: `<review>/notion/suggestions`: the Notion pages the pull request's description links to, offered for linking.
- `review-notion.ts`: `<review>/notion`: the Notion pages a pull request under review is linked to (its `notion` specs).
- `review-preview.ts`: `<review>/preview`: a pull request's preview, its checkout and its e2e result, as commands the worker runs.
- `review-removal.ts`: What goes with a removed pull request under review: its commands not handled yet, its container and volumes, its files.
- `review-reports.ts`: Spec report routes under a review's base: `/reports` and its `cancel`, `gaps` and `attention` subroutes.
- `review-runs.ts`: `<review>/runs`: commands the user runs in a pull request's own checkout, and their output added to the review.
- `review-specs.ts`: `/specs` under a review's base: the review's specs, started the first time, each read from its source unless edited.
- `review-tracker-fields.ts`: `<review>/tracker-fields`: sets one property of a page or issue the review is linked to; the worker sends it.
- `review-trackers.ts`: The routes of a pull request under review about the trackers' items it implements: Notion pages, Jira issues.
- `review-workspace.ts`: The routes of a pull request under review about its own checkout, commits and links.
- `review.ts`: A ticket's review routes: its diff, its comments, the agent review, the pull request import, and sending the review.
