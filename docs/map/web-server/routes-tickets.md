# Map: `apps/web/src/routes/tickets/`

Ticket routes: create, edit, detail, flow, base and retarget, links, Jira and Notion links, commits, pull request, stack, workspace, removal, resync.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `ticket-base.ts`: The API routes that show and change the branch a ticket is based on.
- `ticket-command-checks.ts`: What a command needs besides a valid move of the state machine.
- `ticket-commits.ts`: `/api/tickets/:id/commits`: the commits stored with the ticket's diff snapshot, and their files.
- `ticket-create.ts`: `POST /api/tickets`: a new ticket; one imported from a tracker (Notion) keeps the item's images and files as its own.
- `ticket-detail.ts`: A ticket as the API answers with it: its summary, and the detail the ticket panel opens with.
- `ticket-edit.ts`: `PUT /api/tickets/:id/text`: the user's new title and description, queued for the worker to write to the issue.
- `ticket-flow.ts`: The steps a ticket runs: read from a request, and `PUT /api/tickets/:id/flow` while it is in Backlog.
- `ticket-jira-link.ts`: `/api/tickets/:id/jira`: links a ticket to a Jira issue after creation, or unlinks it; Jira is only read.
- `ticket-links.ts`: Ticket summaries and parent links: the stack, the children, and the check before a start.
- `ticket-notion-link.ts`: `/api/tickets/:id/notion`: links a ticket to its Notion page after creation, or unlinks it.
- `ticket-origin.ts`: A new ticket's origin (the tracker item it is imported from), and that item's images and files kept as the ticket's.
- `ticket-outside-links.ts`: A ticket's links outside Union: its GitHub pull request, its tracker item (Notion page, Jira issue).
- `ticket-pull-request.ts`: Links a ticket to a pull request (looked up on GitHub, read only), or unlinks it.
- `ticket-removal.ts`: Removes a cancelled ticket from Union: its runs, outputs, reviews and files go with it.
- `ticket-resync.ts`: The API route that asks the worker to reset a ticket's workspace onto its branch as GitHub has it, after it moved there.
- `ticket-retarget.ts`: The API route that asks the worker to move a finished ticket's commits onto another base branch.
- `ticket-review-subroutes.ts`: A ticket's routes about its change: refused commit, PR description, specs, line explanations, spec report, review.
- `ticket-stack.ts`: A split ticket's stack as the API shows it: its slices, what merged where, and whether a restack is due.
- `ticket-subroutes.ts`: The routes under `/api/tickets` that have their own module: creation, imports, a ticket's files, preview, removal.
- `ticket-workspace.ts`: The routes about a ticket's workspace: its base branch, the steps it runs, its title and description, its commands.
- `tickets.ts`: The API routes for tickets: listing, creating, editing outputs and moving them between steps.
