# Map: `apps/web/src/`

Server code, flat: the Hono app and server, API types (`*-types`), GitHub reads (repository, pull requests, checks, commits, stacks, onboarding), Jira and Notion reads and comment commands, review and pull request import, guide pages, caches.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `api-integration-types.ts`: The integrations' shapes the API answers with: a connected tracker without its secret, an item to import.
- `api-pr-import-types.ts`: What the pull request import reads from GitHub, and the preview the API answers with.
- `api-size-types.ts`: What the API answers about the size of a ticket's change: its lines of code against its budget.
- `api-stack-types.ts`: A split ticket's stack, as the API sends it with the ticket.
- `api-types.ts`: The shapes the API answers with, as the browser sees them: tokens and keys never leave the server.
- `app.ts`: Builds the web server's Hono app: error handling and the API routes, wired to the database and GitHub.
- `ci-api-types.ts`: The pull request's CI checks as the PR tab shows them, and what the user gave the implementer from them.
- `ci-load.ts`: Loading a ticket's PR checks: the ticket, the pull request picked, the credentials, and GitHub's listing.
- `ci-picks.ts`: The user's picks among the pull request's CI, checked against its current checks.
- `ci-rerun.ts`: Which check of the pull request can be run again (a failed GitHub Actions job), and the command that asks the worker to.
- `event-api-types.ts`: What the event rule routes answer with: the rules, their deliveries, previews and choices.
- `github-check-parse.ts`: GitHub's check runs, commit statuses and comments to the PR tab's shape: states, workflow runs, bot comments.
- `github-checks.ts`: The web's reads of a pull request's CI: its checks and bot comments, and what a pick gives the agent.
- `github-commits.ts`: Reads a pull request's commits, and one commit's files, from GitHub.
- `github-credentials.ts`: The GitHub credentials a wizard request carries: a token, or an installation of the stored GitHub App.
- `github-discussion.ts`: Reads a pull request's discussion from GitHub: its title and description, line threads, review summaries and comments.
- `github-onboarding.ts`: GitHub calls the web server makes itself, because the UI needs the answer right away.
- `github-pr-import.ts`: Reads a pull request to import as a ticket, in one GraphQL query: its branches and head, and the issues it closes.
- `github-project-link.ts`: Connecting a project to a GitHub Project, or disconnecting it: the columns the worker's board sync reads.
- `github-pull-request-files.ts`: Reads a pull request's head commit, branches and changed files from GitHub, ready to review.
- `github-pull-requests.ts`: Reads the repository's newest pull requests from GitHub, for the Pull requests tab.
- `github-queries.ts`: The GraphQL queries the web server sends GitHub: Projects, a pull request's threads and notes, pull request lists.
- `github-repo-reads.ts`: The web's repository and Project reads from GitHub: branches, an issue, and what a rule picks from.
- `github-repo.ts`: Reads a repository's branches and issues from GitHub.
- `github-repository.ts`: The Repository tab's reads from GitHub: the commit a branch or sha names, a tree, a file's bytes.
- `github-rule-choices.ts`: What a pull request rule can pick from the repository: its labels and the users who can be assigned or asked to review.
- `github-stacks.ts`: The web's reads of GitHub's stacks of pull requests: the repository's open ones, or the one holding a pull request.
- `guide-pages.ts`: The user guide's pages from the files of `documentation/`: which names are pages and their titles.
- `guide-types.ts`: The user guide as the API serves it: its pages in the guide's order, and one page's text.
- `http.ts`: HTTP status codes and small helpers the web routes use to read requests and fail.
- `pending-comments.ts`: The comments a ticket's tracker tab is still sending: queued commands the worker has not answered with an event yet.
- `pr-import-plan.ts`: What a pull request becomes on import: its issue, the planning steps read from Union's comments there, the flow.
- `pr-import-ticket.ts`: Creates the ticket a pull request is imported as: on its branch and base, its planning steps prefilled.
- `pr-replies.ts`: A pull request's replies as the UI reads them: those the worker has not posted yet, the implementer's suggestions.
- `pr-reply-commands.ts`: Replies to a pull request's comments, as the web hands them to the worker.
- `project-counts.ts`: Each project's tickets that wait on the user and those running, for the sidebar: one read of the tickets.
- `public-project.ts`: A project and its integrations as the browser sees them: no secret, no token (server only).
- `pull-request-ref.ts`: A pull request of the repository: `12`, `#12` or its `/pull/12` URL.
- `reply-api-types.ts`: What the API answers about replies to a pull request's comments: those being posted, the implementer's suggestions.
- `repository-api-types.ts`: The Repository tab's answers: the commit a branch or sha names, the folders and files at it, one file.
- `repository-cache.ts`: Keeps the Repository tab's trees and files in memory: both are named by their sha, so they never change.
- `request-guard.ts`: Refuses API requests from anywhere but Union's own page: other hosts, other origins, form bodies.
- `restart-watch.ts`: Ends the web's container when an update asks Union to restart (`union_restart`).
- `review-feedback.ts`: The review the user sends, as the implementer receives it.
- `review-import-refusal.ts`: When a tracker's comment (a Notion discussion, a Jira comment) can go into a ticket's review: once it is implemented.
- `review-import.ts`: Turns a pull request's unresolved threads and review notes into draft review comments on the ticket.
- `review-output-comment.ts`: A command's or the e2e tests' output as a review comment: what ran, how it ended, the last lines in a code block.
- `review-preview-types.ts`: What a pull request under review's Preview tab reads: its preview, its checkout and its commands.
- `review-spec-types.ts`: What a review's Specs bar reads: each spec, with the text to use now or why it could not be read.
- `review-tracker-types.ts`: What a pull request under review's tracker tab reads: its linked items, with their text and comments as read now.
- `rule-previews.ts`: What a rule's action would do for one ticket, one preview per kind of action; nothing is sent.
- `running-previews-types.ts`: The previews running across projects, as the Previews page and the sidebar's count read them.
- `server.ts`: The web server's entry point: opens the database, migrates it and serves the API and the client.
- `services.ts`: The outside services the API routes may call: GitHub and Notion.
- `shared-services-types.ts`: What the Environments tab's Shared page reads of the project's shared services.
- `slice-snapshot.ts`: The diff a ticket's comments are anchored in: its whole change, or one slice's own change when split.
- `stack-checks.ts`: The CI of a split ticket's open slices, one count per check state for each slice's pull request.
- `ticket-origin-guard.ts`: A ticket comes from one tracker at most: linking it to another one's item, or unlinking another one's, is refused.
- `ticket-pull-request.ts`: The pull request a ticket's PR tab reads: its own, or one of its stack's slices' picked with `?pr=`.
- `ticket-size.ts`: A ticket's change as its Overview shows it: lines of code added against its budget, from its latest diff snapshot.
- `ticket-tracker-item.ts`: A ticket's tracker item as the `/trackers/:kind` routes read it: the kind, the item, and the project's integration.
- `tracker-comment-commands.ts`: Comments on a ticket's tracker item as the web hands them to the worker: one queued, and those not posted yet.
- `tracker-comment-types.ts`: What a ticket's tracker tab reads about its item's comments: the threads read now, those being sent, the review's.
- `tracker-field-commands.ts`: Properties of a tracker's item set by hand, as the web hands them to the worker: one queued, and those not sent yet.
- `tracker-field-input.ts`: What a tracker tab sends to set one property: read from the request, checked by the tracker's adapter, queued.
- `tracker-field-types.ts`: What a tracker tab reads about the properties being set: the changes the worker has not sent yet.
- `tracker-item-types.ts`: What a tracker tab reads about the item itself, for its card: one shape for every tracker.
- `tracker-review-import.ts`: Adds a thread of a ticket's tracker item, or one comment of it, to the ticket's review as a general draft.
- `union-update-types.ts`: Union's own update as the sidebar reads it: the last check, the update's state, and the work a restart would interrupt.
- `weighted-lru.ts`: A least-recently-used map bounded by the summed weight of its values (bytes, or a count).
