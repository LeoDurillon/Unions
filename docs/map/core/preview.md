# Map: `packages/core/src/preview/`

Previews: records, the compose file and its checks, config, memory caps, secrets, e2e screenshots and staleness, workspace owner, shared services.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `e2e-screenshots.ts`: The screenshots kept from a ticket's last e2e run: ticket files the next run replaces.
- `e2e-staleness.ts`: Whether a preview's last e2e result still describes it: the preview restarted or the code changed since.
- `preview-compose-check.ts`: Checks that a resolved compose file can run as a preview, and the keys and paths Union adds to it.
- `preview-compose-reserved.ts`: Names a preview may not take: a build tagged as an image Union runs, and volumes or networks named like Union's.
- `preview-compose.ts`: The file the preview runs, written from the resolved one after `composeProblems` found nothing.
- `preview-config.ts`: Preview settings and their templates.
- `preview-memory-caps.ts`: What each service of a preview may use: Union's memory cap and the preview's CPU cores.
- `preview-proxy-network.ts`: The network one preview's exposed services share with the proxy, and with no other preview.
- `preview-screenshots.ts`: A pull request's e2e failure screenshots: files under its own folder, listed in `preview_screenshots`.
- `preview-secrets.ts`: The names of the project's secret preview variables: all the browser ever sees of them.
- `preview-shared-commands.ts`: A shared service's own settings as they are sent, checked, and the commands a preview runs, its templates filled in.
- `preview-shared-proxy.ts`: The web pages of a project's shared services, opened by the proxy at one address per project.
- `preview-shared.ts`: Services shared between a project's previews, written as the shared compose project Union runs once.
- `previews.ts`: Preview records: compose project and host, state, generated or user file, e2e results, and recovery after a stop.
- `shared-stacks.ts`: The record of a project's shared services: written by the worker from Docker's state, read by the Environments tab.
- `workspace-owner.ts`: Whose workspace a preview or a command runs in: a ticket's, or a pull request's under review; browser-safe.
