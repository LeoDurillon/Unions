# Map: `packages/core/src/ticket/`

Tickets: records and dispatch, links and base, Needs you, start over, attachments, project files and scripts, command and CI outputs, refused commits.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `agent-inputs.ts`: What the user gave the implementer's next run: command outputs and CI outputs, read together and marked read together.
- `approval-next.ts`: What approving a ticket's step starts: the next step and the model it runs on, as the worker will run it.
- `attachment-limits.ts`: Upload limits, shared by the server and the browser (which checks them before sending).
- `attachments.ts`: A ticket's files: where they live on the host and in the container, their names, and which a push must not contain.
- `ci-output-text.ts`: The text the implementer gets from CI: a failed check, another job's log, a bot's comment.
- `ci-outputs.ts`: CI output given to the implementer: kept for its next run, or sent now as a revision with the user's note.
- `container-runs.ts`: Commands the user runs in a workspace: queued, their output kept, and handed to the implementer.
- `needs-you.ts`: Whether a ticket waits on the user (the rule the board's Needs you filter, `n` and the sidebar's counts share), and whether a notification still asks something of them (the bell's count).
- `project-files.ts`: Files the user gives a project: kept on the host, put at a path in the repository, and never pushed.
- `project-scripts.ts`: The project's saved scripts: checked as the settings store them, and the run each one queues.
- `refused-commits.ts`: Refused commits: the ticket's last one, and the user's decision on it.
- `start-over.ts`: Start over: a planning or custom step that waits for the user, or stopped, runs again from scratch.
- `ticket-base.ts`: The branch the ticket starts from and why; before it starts, the one it would take now.
- `ticket-links.ts`: Parent links between tickets, and the branch a ticket starts from (`ticketBase`).
- `tickets.ts`: Tickets: reading, creating and labelling them, the event log they write to, and dispatching state-machine actions.
