# Map: `packages/core/src/schema/`

The Drizzle schema, one file per group of tables, and their shared column types.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `schema-agent-images.ts`: A project's own agent image: the one its agents run on, the one saved and not applied yet, and its build's state and log.
- `schema-agent-log.ts`: The agents' raw output, line by line, kept apart from the event log.
- `schema-agent-tool-usage.ts`: What each agent call did with its tools: calls, errors, refusals and output size per tool key, written from its `result` line.
- `schema-agent-usage.ts`: What each agent call consumed, per model: written from its `result` line in `agent_log`.
- `schema-attachments.ts`: Files the user attached to a ticket, stored on the host under the attachments folder and copied into the ticket's container for the agents.
- `schema-ci-outputs.ts`: CI output the user gave the implementer from the pull request's checks: a failed check, another job's log, a bot's comment.
- `schema-container-runs.ts`: A command the user ran in a workspace: a ticket's (its container, in the checkout, as the agent) or a pull request's under review (exactly one of `ticket_id` a…
- `schema-custom-agents.ts`: The user's own agents: a name and a role, and the prompt the worker's prompt writer wrote from them.
- `schema-diff-commits.ts`: A ticket's commits at its diff snapshot, oldest first, each with its own files against its first parent.
- `schema-events.ts`: Event rule tables: the rules, their deliveries, and the event log's readers.
- `schema-integrations.ts`: The outside trackers a project is connected to (Notion): secret, config and the tracker's columns as read.
- `schema-lesson-suggestions.ts`: The lesson writer's and tidier's runs: the feedback the user gave the writer, and the lessons proposed.
- `schema-mcp.ts`: The claude.ai connectors of the Claude account the agents run with, as the last check read them (`claude mcp list` in a throwaway container).
- `schema-notifications.ts`: What needs the user, drawn from the event log by the worker: one row per event that notifies, read in the bell's panel.
- `schema-pr-descriptions.ts`: A pull request description the agent rewrote for a ticket whose work changed after the PR was opened.
- `schema-previews.ts`: A preview: its compose project (`union-t<id>` for a ticket, `union-r<id>` for a pull request under review) run from its owner's workspace, served by the proxy …
- `schema-project-files.ts`: Files the user gave the project (a database dump, a local config), put at `path` in every ticket's workspace and kept out of git there.
- `schema-refused-commits.ts`: Changes the agent left uncommitted that the repository's hook refused to commit.
- `schema-review-agent-runs.ts`: A review agent's runs on a review's change, asked from its review page: the markdown it answered, or why it failed.
- `schema-review-explanations.ts`: The table of the explanations an agent gives of lines of a review's diff, and what one holds.
- `schema-review-groupings.ts`: The agent's grouping of a review's changed files by the parts of a specification, run when the user asks: for a ticket's branch or a pull request under review …
- `schema-review-reports.ts`: The agent's report comparing a review's change with its specs, run when the user asks: for a ticket's branch or a pull request under review (`review_comments` …
- `schema-review-runs.ts`: The columns an agent run on a review shares (grouping, explanation, report): its owner and its status.
- `schema-review-specs.ts`: The specs a review checks its change against (a ticket's or a pull request's under review): the list the Specs bar shows, read by Review with agent, Explain an…
- `schema-reviews.ts`: Pull requests the user put under review from the Pull requests tab, without a ticket.
- `schema-shared-stacks.ts`: The services a project's previews share (`union-p<id>-shared`), as the worker last saw them in Docker: for the Environments tab, since the web never asks Docke…
- `schema-ticket-slices.ts`: The slices of a ticket split into a stack of pull requests: a part of the spec and its commits.
- `schema-types.ts`: Plain types stored in JSON columns, kept apart so schema.ts holds the tables.
- `schema-union-settings.ts`: The one-row table of Union's machine settings: how much memory and how many CPU cores its containers may use.
- `schema-union-update.ts`: The one-row table of Union's own update: the checkout against the remote's `main`, and the update's state.
- `schema.ts`: The main tables: projects, the GitHub App, tickets, runs, outputs, events, commands, memory, agents and investigations.
