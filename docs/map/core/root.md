# Map: `packages/core/src/`

Shared code, flat: the state machine and phases, agents, their prompts, tools, usage and lessons, Docker (runtime, docker-cli, limits), GitHub auth and clients, tickets, flows, stacks and slices, diffs, pull request descriptions, investigations, notifications, Union settings and update.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `active-work.ts`: The work in progress a restart interrupts, per table: `bun run active` and the Update dialog list it.
- `agent-activity.ts`: What an agent says or does in one `claude -p` stream-json event, in a short line.
- `agent-denied.ts`: The commands Union denies its agents, whatever their tools or the repository's settings: for every run, and per step.
- `agent-environment.ts`: The agent's environment settings as sent (`agentVariables`, `forwardPorts`, `startForImplementation`), checked.
- `agent-image-source.ts`: A project's own agent image: the Dockerfile or image the user gives, checked and rewritten onto the base images.
- `agent-images.ts`: A project's own agent image in the database: saved by the web, then built, applied or failed by the worker.
- `agent-inputs.ts`: What the user gave the implementer's next run: command outputs and CI outputs, read together and marked read together.
- `agent-log.ts`: Writes the agents' output to `agent_log`, and reads a Log: events and agent lines in one order.
- `agent-review-specs.ts`: The specifications an agent review is given: read from the request, and written into the agent's prompt.
- `agent-reviews.ts`: Agent review records: queued, claimed, finished and cancelled, with the draft comments they leave.
- `agent-tool-calls.ts`: Counts an agent call's tool uses from its stream-json lines: calls, errors, refusals and output size per tool key.
- `agent-tool-key.ts`: What an agent's tool call is about, for counting: the command family and shape, the file read, the skill or subagent.
- `agent-tool-record.ts`: Records an agent call's tool uses (`agent_tool_usage`) from its lines in `agent_log`, live or replayed from the past.
- `agent-tools.ts`: The tools agents run with: the defaults, Claude Code's built-in ones, and the list the user adds to.
- `agent-usage-record.ts`: Records an agent call's usage from its `result` line in `agent_log`, live or replayed from the past.
- `agent-usage-totals.ts`: What a ticket's or an investigation's agent calls used, per run and per call, summed for the Usage tables.
- `agent-usage.ts`: Reads what a `claude -p` call consumed from its stream-json events: tokens per model, and its peak context.
- `agents.ts`: The agents' default prompts, models, efforts and tools, the user's overrides, and how a run resolves them.
- `ansi.ts`: Strips terminal colour codes from command and CI output; browser-safe.
- `approval-next.ts`: What approving a ticket's step starts: the next step and the model it runs on, as the worker will run it.
- `attachment-limits.ts`: Upload limits, shared by the server and the browser (which checks them before sending).
- `attachments.ts`: A ticket's files: where they live on the host and in the container, their names, and which a push must not contain.
- `branch-move.ts`: When a ticket's branch moved on GitHub away from what Union last pushed, and what that holds back until a resync.

- `change-budget.ts`: A ticket's size budget and whether a change goes over it.

- `ci-output-text.ts`: The text the implementer gets from CI: a failed check, another job's log, a bot's comment.
- `ci-outputs.ts`: CI output given to the implementer: kept for its next run, or sent now as a revision with the user's note.
- `claude-limits.ts`: How much of the Claude subscription's usage windows (five hours, seven days) is used.
- `compose-containers.ts`: Reads `docker ps` lines of a compose project's containers, and which of its exposed services stopped.
