# Map: `apps/web/client/lib/ticket/`

A ticket's actions and data: commands and edits queued for the worker, progress, what it needs now, answers, files, origin, refused commits, workspace commands, the Steps tabs.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `answers.ts`: Splits an output at its `Answer:` lines, where the user answers the intake step's questions, and writes the answers in.
- `attachments-api.ts`: A ticket's files from the browser: checked before sending, uploaded, and their download links.
- `refused-commit-api.ts`: The ticket's last refused commit, or null.
- `ticket-attention.ts`: What the ticket needs from the user now, in a sentence: a step to read or answer, a stop to look at, a start.
- `ticket-origin.ts`: What the ticket panel says about the tracker item a ticket was imported from (a Notion page).
- `ticket-progress.ts`: The ticket's way through its flow, one stop per step then Done and Merged: what each did, or does now.
- `use-branch-resync.ts`: Asks the worker to resync the ticket's workspace onto its branch on GitHub: queued, done when its event comes in.
- `use-container-runs.ts`: The commands run in the target's workspace (polled while one is on), and running or stopping one.
- `use-create-ticket.ts`: Creating a ticket from the New ticket form, then uploading its files one by one.
- `use-queued-work.ts`: Work the worker finishes later: the request is sent, then waited on until the ticket's done or failed event comes in.
- `use-run-agent.ts`: What a ticket's command output can do with the implementer: wait for its next run, or go now as a revision.
- `use-ticket-commands.ts`: The hook that sends commands for a ticket and refreshes what the page shows afterwards.
- `use-ticket-edit.ts`: Saves the ticket's edited title and description: queued for the worker, done when its event comes in.
- `verdict.ts`: The reviewer's verdict line (`VERDICT: APPROVED` / `VERDICT: CHANGES_REQUESTED`), if any.
- `worker-tabs.ts`: The Steps tab's own tabs: a step's in the ticket's flow order (custom agents named), the on-demand ones, the log.
