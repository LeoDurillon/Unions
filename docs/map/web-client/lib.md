# Map: `apps/web/client/lib/`

Client logic, flat: API clients (`*-api`), hooks (`use-*`) for data, state and keys, the event stream and live invalidation, URL state, filters, formatting, notifications.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `agent-events.ts`: Condenses one raw `claude -p` stream-json event into zero or more log lines.
- `agent-image-starters.ts`: The Dockerfiles the agent image page offers to start from: JavaScript extras, Python, Rust, Go and PHP.
- `answers.ts`: Splits an output at its `Answer:` lines, where the user answers the intake step's questions, and writes the answers in.
- `api.ts`: The browser's client for the `/api` routes, and the errors they answer with.
- `attachments-api.ts`: A ticket's files from the browser: checked before sending, uploaded, and their download links.
- `board-filter.ts`: Which tickets the board shows: a text search (title, issue or PR number) and where they came from.
- `board-order.ts`: The order of a board column's cards: those that need the user first, then the newest.
- `card-steps.ts`: A board card's flow as a row of segments: the steps done, the one it is on (running, waiting, stalled), the rest.
- `choice-values.ts`: Multi-select rule values: option names joined by commas, split the same way as in the worker.
- `custom-agents-api.ts`: The browser's client for the custom agents endpoints: create, edit, regenerate the prompt, delete.
- `desktop-notifications.ts`: Desktop notifications: off until the user turns them on, shown by the one tab that holds the event stream.
- `diagram-export.ts`: Turns a drawn diagram's SVG into files to download: the SVG itself, or a PNG at twice its size.
- `diff-selection.ts`: Which lines of a diff a comment covers: clicks, shift-clicks, whole hunks and whole files.
- `download.ts`: Has the browser save a file built in the page.
- `duration.ts`: How long something took, as the ticket panel says it: "45s", "3m 23s", "1h 22m".
- `env-lines.ts`: `KEY=value` lines to variables and back; blank lines and `#` comments are skipped.
- `environments-url.ts`: The project's Environments tab in the URL (`?view=environments&env=variables`): its pages, opening it from elsewhere.
- `event-hub.ts`: The browser's one shared event stream, handed to every listener in any tab.
- `event-rules-api.ts`: The browser's client for the event rules endpoints.
- `file-tree.ts`: The files as a directory tree, for the review's file list.
- `finding-text.ts`: How the Usage page words each finding: its title, what to do about it, and the figure of each item.
- `flow-layout.ts`: Lays out a spec report's map in layers, top to bottom, each node ordered in its layer near the nodes it comes from.
- `getting-started.ts`: The getting-started checklist's steps, each ticked from what the project's tickets and settings say.
- `github-access-save.ts`: Changing how a project reaches GitHub: a token or an installation, verified against GitHub before it is stored.
- `github-markdown.ts`: Renders GitHub comment text as GitHub does: its HTML (folds, images) sanitized, and `> [!NOTE]` alerts.
- `github-project-api.ts`: The browser's client for a project's GitHub Project: the Projects to pick from, connecting one, disconnecting it.
- `heading-slug.ts`: The id GitHub gives a Markdown heading, so the guide's `page.md#heading` links land on it.
- `help-requests.ts`: Help asked for from the sidebar's Help menu (the keyboard shortcuts, a project's getting-started checklist).
- `highlight.ts`: Syntax highlighting for the review's diffs, the repository's files and the code fields, with highlight.js.
- `integrations-api.ts`: The browser's client for the integration endpoints, and a project's integration of a kind.
- `investigate-ticket.ts`: Opens Investigations with a new investigation on the ticket ready to write (`?investigate=<id>`).
- `investigation-groups.ts`: The investigations list's sections (This week, Last week, then by month), its short dates and its search.
- `labels.ts`: Board labels: the columns, what a ticket is doing, its reference, and whether it waits for its parent.
- `leave-guard.ts`: Unsaved settings: the forms holding changes, and asking before a navigation throws them away.
- `line-diff.ts`: The lines of `after` against `before`: kept, added or removed, in reading order.
- `live-invalidation-keys.ts`: Which cached queries an event makes stale: board, ticket, investigations, notifications, the review page's side runs.
- `log-runs.ts`: Splits the log at each run header, so every run can fold on its own.
- `markdown-links.ts`: Where a repository Markdown file's links and images go.
- `mermaid-render.ts`: Draws Mermaid source as SVG, for the screen (in its color scheme) or for a file (light, with plain-text labels).
- `needs-you-action.ts`: What a ticket that needs the user asks of them, in a few words: the step to read, the run that failed, red CI.
- `next-needing.ts`: The next ticket that waits on the user, in the board's order: column by column, each as it lists them.
- `nice-scale.ts`: A chart's value axis: a round top just above the largest value, and the ticks up to it.
- `notification-groups.ts`: The notifications grouped by what they are about (a ticket or an investigation), newest group first.
- `notifications-api.ts`: The browser's client for the notifications: a page of them, marking them read and clearing them.
- `offered-action-kinds.ts`: The kinds of action the rule editor offers: those of the trackers and GitHub layers the project has, and Union's.
- `open-notification.ts`: Opens what a notification is about (its ticket or investigation, in its project) and marks it read.
- `opened-investigation.ts`: The investigation opened from elsewhere (a notification), in the URL (`?investigation=<id>`).
- `path-filter.ts`: Finds files by a few typed letters, like an editor's "go to file": the letters in order, anywhere in the path.
- `pr-description-api.ts`: The browser's client for a ticket's pull request description endpoints; `pr` picks a slice's draft.
- `pr-import-api.ts`: Importing a pull request of the project's repository as a ticket: its preview, then the ticket.
- `project-files-api.ts`: The browser's client for a project's uploaded files.
- `pull-request-stacks.ts`: Stacks in the Pull requests tab and its Under review part, by GitHub's stacks.
- `refused-commit-api.ts`: The ticket's last refused commit, or null.
- `relative-time.ts`: Times as the panels say them: "5 min ago" for when something happened, "1:12" for how long it runs.
- `repo-links.ts`: Where a file or folder of the repository is on GitHub, and a file's size in words.
- `repo-paths.ts`: Where a relative link in a repository file points: `../docs/a.md` from `src/README.md` is `docs/a.md`.
- `repo-tree.ts`: The repository's entries as folders, each with its children in the order the tree shows them.
- `repository-api.ts`: The Repository tab's reads: the commit a branch names, the tree at it, one file.
- `repository-url.ts`: The Repository tab in the URL (`?view=repository&repo-ref=main&repo-path=src/a.ts`).
- `settings-sections.ts`: The project settings pages by group, and opening or closing them through `?settings=`.
- `setup-api.ts`: The browser's client for the setup agent: its latest run with the proposal, and starting one.
- `setup-follow-up.ts`: The follow-up that answers the setup agent's questions and asks it for its whole proposal again.
- `shortcuts.ts`: Single-key shortcuts: which key a keydown means, and the hook that listens.
- `slice-view.ts`: Which comments a split ticket's review shows on each tab: a slice's on its own, the rest on All.
- `spec-hunks.ts`: What a file opened under a part of the spec shows: that part's hunks, and the parts each hunk serves.
- `split-rows.ts`: Pairs a patch's lines for side-by-side display.
- `stream-status.ts`: Whether the live event stream is connected, for the sidebar's "Reconnecting…" pill.
- `strip-ansi.ts`: Removes the terminal's colour and cursor codes from output shown as plain text.
- `tab-keys.ts`: Arrow keys in a tab bar (`role="tablist"`): Left and Right move to the previous or next tab, Home and End to the ends.
- `ticket-attention.ts`: What the ticket needs from the user now, in a sentence: a step to read or answer, a stop to look at, a start.
- `ticket-origin.ts`: What the ticket panel says about the tracker item a ticket was imported from (a Notion page).
- `ticket-progress.ts`: The ticket's way through its flow, one stop per step then Done and Merged: what each did, or does now.
- `token-counts.ts`: A call's tokens as the Log shows them, from its `result` event: input with its cached share, output with its thinking.
- `union-settings-groups.ts`: The Union settings pages, by group: the order of the All agents table and of `?union=` pages.
- `union-settings-sections.ts`: The Union settings page open in the URL (`?union=implement`), and opening or leaving it.
- `url-state.ts`: Sets or removes (`null`) query parameters as one history entry, and tells every reader.
- `usage-format.ts`: How the Usage tables write a total: input with its cached share, output, API-equivalent cost, peak context.
- `use-active-project.ts`: The project list plus the remembered selection, falling back to the first project.
- `use-agent-form.ts`: An agent's page form in the Union settings: its prompt, model, effort and tools, saved together, and its reset.
- `use-agent-image.ts`: A project's agent image on its settings page: what runs, what was saved, its build, and saving or dropping a choice.
- `use-agent-tools.ts`: The tools agents pick from: built-in ones and the ones the user added.
- `use-app-state.ts`: What the root layout runs on: live refetching, the projects, the open ticket, navigation, and opening notifications.
- `use-board-keys.ts`: The board's keys while no ticket is open: / goes to the search, n opens the first ticket that needs the user.
- `use-branch-resync.ts`: Asks the worker to resync the ticket's workspace onto its branch on GitHub: queued, done when its event comes in.
- `use-ci-rerun.ts`: Asks the worker to run a failed GitHub Actions job again, and remembers it was asked until GitHub shows the new run.
- `use-commits.ts`: The change's commits, oldest first, and (tickets) the change since the last review.
- `use-compact-sidebar.ts`: Whether the sidebar is folded to an icon rail, remembered in this browser; folded at first on a narrow window, or while there is only one project to switch to.
- `use-connectors.ts`: The account's claude.ai connectors, and reading them again (polled while the worker checks).
- `use-container-runs.ts`: The commands run in the target's workspace (polled while one is on), and running or stopping one.
- `use-current-reviews.ts`: The pull requests under review without a ticket, and adding or removing one.
- `use-custom-agent.ts`: A custom agent's changes from its page: rewriting its role, regenerating its prompt, deleting it.
- `use-custom-agents.ts`: The custom agents as the ticket views and flow pickers need them: names by step, and the ones a flow can add.
- `use-dismiss.ts`: Closes a popup (a menu, a picker) on Escape or a click outside the element that holds it and its button.
- `use-event-stream.ts`: Calls `onEvent` with every new event, from the browser's one shared stream (`event-hub.ts`).
- `use-folded-columns.ts`: Which board columns are folded to a narrow strip, remembered in this browser; Merged / Closed starts folded.
- `use-getting-started-shown.ts`: Whether a project's getting-started checklist shows.
- `use-github-app.ts`: The global GitHub App's status; saving or removing it invalidates `['github-app']`.
- `use-live-invalidation.ts`: Refetches board, ticket, investigation and notification data whenever the worker records a change.
- `use-log.ts`: Polls a ticket's or an investigation's Log while it is shown: all of it first, then what is new.
- `use-memory.ts`: The Memory page's data: lessons and feedback, saving them with the on/off switch, curating feedback.
- `use-models-form.ts`: The All agents table's form: every agent's model and effort.
- `use-navigation.ts`: Which page is shown (`?page=previews`, `?union=` for the Union settings, else the board) and which overlay is open.
- `use-notifications.ts`: The notifications, page by page, with how many are unread and how many still ask something (also in the tab's title), marking them read and clearing them.
- `use-now.ts`: The current time, read again every second while `ticking`: for clocks that count while something runs.
- `use-pr-checks.ts`: A pull request's CI checks (the ticket's or a slice's), and giving picks of them to the implementer.
- `use-pr-description.ts`: A pull request's description rewrite: its latest draft, and rewriting, sending, discarding or cancelling it.
- `use-pr-replies.ts`: The replies of one pull request (pending, suggested, who posts) and their mutations.
- `use-project-jump.ts`: `n` on a board with nothing waiting: go to the next project in the sidebar that has tickets waiting on the user.
- `use-project-view.ts`: Which view of the project shows: board, investigations, pull requests, repository, environments or usage.
- `use-queued-work.ts`: Work the worker finishes later: the request is sent, then waited on until the ticket's done or failed event comes in.
- `use-resources-form.ts`: The Resources page's form: how much memory each agent container and each preview service may use, saved together.
- `use-run-agent.ts`: What a ticket's command output can do with the implementer: wait for its next run, or go now as a revision.
- `use-run-progress.ts`: The project's runs in progress: when each started and what its agent did last.
- `use-selected-ticket.ts`: The open ticket, and whether its review is open, live in the URL (`?ticket=3&review=1`).
- `use-settings-form.ts`: A settings page's form: what is edited, whether it differs from what was saved, and its one Save.
- `use-setup-apply.ts`: Applying one part of a setup proposal through the endpoint its settings page uses, then reading the settings again.
- `use-setup-dismissed.ts`: The parts of a setup proposal the user dismissed, remembered per setup run in this browser.
- `use-slice-view.ts`: The slice a split ticket's review page shows: its tabs, its target, its files and its comments.
- `use-stack-checks.ts`: The CI of a split ticket's open slices, read from GitHub when the PR tab opens and every 30 s while a check runs.
- `use-start-output.ts`: The lines a ticket's preview prints while it starts (its build, its services), as they arrive.
- `use-start-tickets.ts`: Starting backlog tickets from the board: shown In progress at once ("Starting…").
- `use-stored-number.ts`: A number remembered in localStorage; storage being unavailable only loses the memory.
- `use-ticket-commands.ts`: The hook that sends commands for a ticket and refreshes what the page shows afterwards.
- `use-ticket-edit.ts`: Saves the ticket's edited title and description: queued for the worker, done when its event comes in.
- `use-union-update.ts`: Union's own update: the worker's last check, checking again, updating, and reloading the page on the new commit.
- `use-usage.ts`: What agent calls used: a ticket's or an investigation's (refetched with them) and a project's over a range of days.
- `verdict.ts`: The reviewer's verdict line (`VERDICT: APPROVED` / `VERDICT: CHANGES_REQUESTED`), if any.
- `worker-tabs.ts`: The Steps tab's own tabs: a step's in the ticket's flow order (custom agents named), the on-demand ones, the log.
