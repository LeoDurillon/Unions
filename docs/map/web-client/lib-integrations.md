# Map: `apps/web/client/lib/integrations/`

Jira and Notion hooks: comments, picks, users, review imports, a ticket's links.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `integrations-api.ts`: The browser's client for the integration endpoints, and a project's integration of a kind.
- `jira-rule-source.ts`: The Jira project a rule's Jira action points at (statuses, settable fields), from the rules list the Events page reads.
- `tracker-draft.ts`: A property's new value while it is edited in a tracker tab: as a rule's value is typed, what is picked, and as read.
- `tracker-value-text.ts`: A value typed for a tracker's property as the user reads it: names for people's ids, Yes or No for a box.
- `use-hidden-fields.ts`: The properties a project hides in its tracker tabs, read with the projects and saved for the project at once.
- `use-jira-picks.ts`: What a Jira field rule can pick (people, versions, components, sprints).
- `use-notion-users.ts`: The Notion workspace members, read only when `enabled` (a person property is in view).
- `use-ticket-jira.ts`: A ticket's Jira issue linked after creation: checking an issue, linking it, unlinking it.
- `use-ticket-notion.ts`: A ticket's Notion page linked after creation: checking a page, linking it, unlinking it.
- `use-tracker-comments.ts`: The comments of a ticket's tracker item, read from the tracker once per opening of its tab, and the comments sent.
- `use-tracker-fields.ts`: Setting a property of a tracker's item by hand, from a ticket's tab or a review's: queued, then followed by its events.
- `use-tracker-item.ts`: A ticket's tracker item for its tab's card (a Notion page, a Jira issue), read once per opening of the tab.
- `use-tracker-review-import.ts`: Add to review on a tracker's thread, or on one comment of it.
