# Map: `apps/worker/src/stack/`

Stacks: splitting a branch into slices, publishing, pushing, following and revising them.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `slice-description.ts`: A slice's pull request description: written by the split's session from the repository's template, or rewritten later.
- `split-agent.ts`: The implementer's session asked to rewrite its commits into the approved slices, and the split's report.
- `split-plan-step.ts`: The split plan: a read-only agent proposes the slices of a stack, which the user edits and approves.
- `split-publish.ts`: The split's way to and from GitHub: the stack's branches fetched with their leases, then pushed and opened.
- `split-rounds.ts`: The agent's turns at rewriting a stack: its first try, then the host's problems sent back until the result passes.
- `split-verify.ts`: Checks a split before it is pushed: the same content, every commit in its slice, each slice's checks.
- `split.ts`: Rewrites the ticket's commits into the approved slices with the implementer's session, checks them, pushes the stack and opens it on GitHub.
- `stack-follow.ts`: After a slice of a GitHub stack merged, GitHub rebases the rest itself: the workspace takes its branches as they are.
- `stack-git.ts`: Git for a stack: its commits with their trailers, the lower slices' branches, a slice tip checked out.
- `stack-publish.ts`: Opens the stack on GitHub: a pull request per lower slice, the ticket's own retargeted, their texts, the issue's comment.
- `stack-push.ts`: Pushes every branch of a stack in one atomic push, each leased on what GitHub had: all or none.
- `stack-refs.ts`: A split ticket's slice branches in its workspace: set from the recorded tips, checked, pushed together, recorded again.
- `stack-revise-conflict.ts`: A conflict while moving a revision's commits into their slices, handed to the implementer's session to resolve.
- `stack-revise-git.ts`: The git side of restacking a revision: each slice's commits, the reordering rebase, and its result.
- `stack-revise.ts`: A revision on a split ticket: the implementer is told the slices, then its new commits are moved into them and the stack pushed.
