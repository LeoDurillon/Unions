# Map: `apps/worker/src/`

The worker, flat: its entry, commands and hooks, scheduler and run pool, executor and step outcome, containers and workspaces, credentials, attachments and files sync, prompts, publishing, revision, review checkout, janitor and cleanup.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `agent-services-step.ts`: A step that runs code (implementation, rebase), with the project's agent services beside it.
- `approved.ts`: The latest approved output of every step before `step`, in the order of the ticket's flow.
- `archive-hint.ts`: How to read attached Office files and zip archives with the unzip commands the step's tools allow.
- `attachments-sync.ts`: Puts the ticket's current files in the container, before every step.
- `branch-push.ts`: Force-pushes a rewritten branch with a lease: the ticket's alone, or every slice of its stack together.
- `branch.ts`: A ticket's branch name: `<issue#>-<slug>`, or `union-<ticket id>-<slug>` while it has no GitHub issue.
- `command-cancels.ts`: The cancel commands of the side runs: the id each one carries, and how a queued or a running one stops.
- `command-hooks.ts`: What the commands hand off to the running worker (all asynchronous), and the no-op set for tests and tools.
- `commands.ts`: Handles every pending command once; a failing command is marked handled with its error.
- `container-exec.ts`: Runs a command in the container and collects its output (for short commands, not agents).
- `container-run.ts`: Runs the commands users queue in tickets' and pull requests' workspaces, a few at a time.
- `credentials.ts`: The secret the host's git uses to clone and push, minted right before use (an installation token lives one hour).
- `custom-step.ts`: A custom agent's step: refused without a prompt; after the implementation, it reads the branch against its base.
- `diff-commits.ts`: Reads a change's commits from `git log`, each against its first parent, and the change since the last review.
- `diff-slices.ts`: A split ticket's slices in its diff snapshot: each one's own change, from the slice below to its tip.
- `diff-snapshot.ts`: Replaces the ticket's diff snapshot with `base...HEAD` as it is now in the container, with each commit's own diff.
- `event-dispatcher.ts`: Follows the event log: writes the notifications and queues a delivery for each event a rule waits for.
- `executor.ts`: Every step: planning and custom agents, implementation, final review, and the rebase, simplify and split on demand.
- `gate.ts`: Runs the project's check command in the repository; a timeout counts as red.
- `history-steps.ts`: The steps that rewrite a reviewed branch's history, the code unchanged: simplify, and the split into a stack.
- `hooks.ts`: What the commands hand off to the running worker: all asynchronous, so draining stays synchronous.
- `index.ts`: The worker's entry point: opens the database and starts the scheduler and the GitHub loop.
- `janitor.ts`: Removes containers and volumes: deleted tickets', and the runs a stopped worker left.
- `left-base.ts`: Where the base a ticket left is read from: its merged PR's ref, else its branch, else the workspace's last copy.
- `leftovers.ts`: What the agent left uncommitted: staged, committed with its message, or refused by a hook for the user to decide.
- `lesson-writer-run.ts`: Runs the lesson writer and the lesson tidier the Memory page asks for.
- `mcp-check.ts`: Reads the account's claude.ai connectors as an agent sees them (`claude mcp list`), in a throwaway container.
- `notifier.ts`: Follows the event log and writes a notification for each event that needs the user, announcing it on the stream.
- `planning-step.ts`: A step that writes markdown and changes no file: the planning steps and the custom agents.
- `project-files-sync.ts`: Puts the project's files in a ticket's workspace at their repository paths, hidden from git (`.git/info/exclude`).
- `prompt-writer-run.ts`: Writes the prompts of the custom agents the user created or regenerated.
- `prompts.ts`: Builds a step's prompt: the ticket, its parent and what it changed, its files and the project's.
- `provision.ts`: Creates a ticket's container.
- `publish.ts`: Pushes the ticket's branch from the host (never with a private file) and opens its draft PR once.
- `refused-commit.ts`: Records the refusal and stops the run there: the user decides what to do with the changes.
- `restack.ts`: Moves the rest of a stack onto the base after a slice merged, then targets the base with the new bottom pull request.
- `review-checkout.ts`: A pull request's own container (`union-r<id>`): its checkout at the reviewed commit, for preview, tests and commands.
- `review-previous.ts`: What a final review is told of the one before it: its findings, the feedback sent since, and the commits since.
- `review.ts`: Runs the final review step: a fresh session reviews the branch against the approved plan, never editing.
- `revision.ts`: The feedback a run of `step` must address, if the user asked for changes.
- `run-end.ts`: How a step's run ends once its result is in: as usual, cancelled by the user, or interrupted by the worker stopping.
- `run-pool.ts`: The lifecycle the queued side runs share: claimed within the run slots, cancellable, each finished with its outcome.
- `run-workspace.ts`: Where a user's command runs: the ticket's container with the agent's services, or the pull request's own.
- `scheduler.ts`: Runs one agent step per ticket in `running` phase, within the shared run slots.
- `services-run.ts`: Starts the project's agent services for a run in the ticket's container and forwards their ports to its `localhost`.
- `side-runs.ts`: Starts the work outside the ticket pipeline: investigations, review agents, PR descriptions.
- `slots.ts`: The run slots that cap how many agents run at once, across the pipeline and the side runs.
- `step-outcome.ts`: A step's result from an agent call that hit the usage limit, and when the scheduler retries it.
- `throwaway-container.ts`: Runs work in a throwaway container from the agent image, with only the Claude login, removed after.
- `throwaway-runs.ts`: The side runs that need no repository: reading the account's connectors, the lesson writer and the prompt writer.
- `ticket-base.ts`: Chooses the branch a ticket is cloned from: the user's choice, else the parent's, else the project's base branch.
- `ticket-cleanup.ts`: Removes what a finished ticket holds in Docker (its preview with its built images, its container and volumes).
- `tracker-field-outcome.ts`: Logs how setting a tracker item's property by hand went: `tracker_field_set`, or `tracker_field_failed` with why.
- `tracker-hooks.ts`: The command hooks that write to the trackers: comments on Notion pages and Jira issues, a property set by hand.
- `workspace-git.ts`: Puts the repository on `branch`: the local branch if it exists, else the pushed one, else a new branch from `base`.
- `workspace-hooks.ts`: The ticket workspace's own commands: resyncing its branch from GitHub, showing an imported pull request.
