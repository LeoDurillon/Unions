# Map: `apps/worker/src/event-actions/`

Event rules' actions: GitHub comments, pull requests and Project fields, Jira comments, fields and transitions, Notion, Union notifications.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `github-comment.ts`: The GitHub comment action of a rule: comments on the ticket's issue or pull request.
- `github-project-fields.ts`: The GitHub Project fields action of a rule: sets fields of the ticket's issue item, or of its pull request's.
- `github-pull-request.ts`: The pull request action of a rule: changes the ticket's pull request.
- `github-retry.ts`: Which GitHub failures a rule action tries again later: rate limits, outages and network errors.
- `jira-comment.ts`: The "Comment on the ticket's Jira issue" action of a rule: its text filled in, sent as Jira's rich text.
- `jira-field-picks.ts`: The picked values of a Jira fields rule (a person, versions, components, a sprint) as Jira takes them.
- `jira-field.ts`: The "Set fields of the ticket's Jira issue" action of a rule: values filled in, checked, then sent in one request.
- `jira-target.ts`: What the Jira actions of rules share: the issues they act on, the credentials to reach them, failures as outcomes.
- `jira-transition.ts`: The "Move the ticket's Jira issue" action of a rule: the transition of its workflow that leads to the rule's status.
- `jira.ts`: The Jira actions of rules (move the ticket's issue, set its fields, comment on it), each a target of the dispatcher.
- `notion.ts`: The Notion action of a rule: sets properties of the ticket's Notion page, or the reviewed pull request's linked pages.
- `target.ts`: What a kind of rule action needs to be done: one target per kind, picked by the event dispatcher.
- `union-notification.ts`: The "Notify me in Union" action of a rule: a notification in the bell (and on the desktop, when on) about the ticket.
