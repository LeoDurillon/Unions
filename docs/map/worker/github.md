# Map: `apps/worker/src/github/`

GitHub sync: issues and pull requests, the board and Project fields, CI, comment replies, stacks, inbound changes, and the fake API the tests use.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `api.ts`: The only surface of GitHub the worker uses, and the shapes it passes; tests substitute an in-memory fake.
- `board-sync.ts`: The GitHub Project part of the sync: the ticket's item on the board, its Status column, and the board's moves read back.
- `branch-moved.ts`: Notices when the ticket's branch on GitHub is no longer the commit Union pushed.
- `ci-rerun.ts`: Runs a failed GitHub Actions job of a ticket's pull request again, and logs whether GitHub took it.
- `clients.ts`: Each project's API: its GitHub App installation or its token, `GITHUB_TOKEN` for projects with neither.
- `close-cancelled.ts`: A cancelled ticket's GitHub side: its open pull requests closed, its issue closed as not planned, once.
- `dependency.ts`: Mirrors the ticket's parent as "blocked by" on its issue, once both issues exist.
- `fake-api.ts`: In-memory GitHub for tests.
- `fake-issue-list.ts`: The fake GitHub's issue listing: the issues updated at or after a time, as the REST API's `since` does.
- `fake-project-fields.ts`: The GitHub Project fields of the in-memory GitHub for tests: the fields and what each item holds.
- `fake-pulls.ts`: The pull requests of the in-memory GitHub for tests, their lookups by branch and commit comparisons.
- `fake-stacks.ts`: GitHub stacks in the fake GitHub client: created, unstacked and read back over its pull requests.
- `fake-threads.ts`: The line threads of the in-memory GitHub for tests, with the replies and comments posted on pull requests.
- `follow-base.ts`: The ticket's base follows its pull request's when GitHub moved it: the base merged and deleted, or edited there.
- `hooks.ts`: The commands' hooks that write to GitHub.
- `inbound.ts`: Applies a change read from GitHub to the matching ticket in the database.
- `issue-pull.ts`: Reads title and description edits from the repository's issues, for a project without a GitHub Project.
- `issue-sync.ts`: The issue part of the sync: the ticket's GitHub issue, opened once, and one comment per step kept up to date.
- `loop.ts`: Pushes every second and pulls every `pullIntervalMs()`, one call at a time, until aborted.
- `mirror.ts`: Runs one `GitHubSync` per project, each with the project's own credentials.
- `octokit-api.ts`: The GitHub API implemented with Octokit: issues, pull requests and the project board.
- `octokit-checks.ts`: The CI checks of the worker's GitHub client: a pull request's head commit and the overall state of its checks.
- `octokit-issue-list.ts`: Lists a repository's issues updated since a time with Octokit, leaving out pull requests.
- `octokit-project-fields.ts`: The GitHub Project fields of the worker's GitHub client: reading them, setting one on an item, a pull request's node id.
- `octokit-pull-request-changes.ts`: The issue and pull request changes of the worker's GitHub client, and its pull requests by branch.
- `octokit-stacks.ts`: GitHub's stacked pull requests in the worker's GitHub client: create a stack, unstack it, read a pull request's.
- `octokit-threads.ts`: Replies to a pull request's comments in the worker's GitHub client.
- `pr-comment-reply-target.ts`: Where a reply to a pull request comment goes on GitHub.
- `pr-comment-reply.ts`: Posts a reply to a pull request comment on GitHub and logs how it went.
- `pr-description-send.ts`: Writes the user's version of a rewritten description to the pull request, with Union's links added back.
- `pr-review.ts`: Posts a review's drafts and summary on GitHub as one pull request review, with the user's verdict.
- `pull-request-checks.ts`: Keeps the CI checks' state of the ticket's open pull request current, and logs when they turn red.
- `pull-request.ts`: Keeps the pull request's state current: `pr_state`, `pr_merged_at`, `pr_closed_at` and `behind_by`.
- `queries.ts`: The GraphQL queries the worker sends to GitHub's project board API.
- `render.ts`: What the worker writes on GitHub: issue bodies with our ticket marker, step comments, and their hashes.
- `stack-pull-requests.ts`: A split ticket's pull requests polled together: each slice's state.
- `status.ts`: Maps board columns to the GitHub Project's Status options, and back.
- `sync.ts`: Mirrors one project's tickets to GitHub: issues and step comments, the GitHub Project's board, pull requests.
- `ticket-edit.ts`: Writes the title and description the user edited in Union to the ticket's issue, then to the ticket.
