# Map: `apps/worker/src/rebase/`

Rebasing a ticket on its base: fetch, attempt, the agent on conflicts, publish, retarget, resync.

Generated by `bun run map`; do not edit. Tests are left out. All folders: [the index](../README.md).

- `followed-base-ref.ts`: Before a step of a ticket whose base was followed: the new base brought into the workspace, which may never have had it.
- `rebase-agent.ts`: Rebases and history rewrites in the implementer's own session, and the report of what the host checked and pushed.
- `rebase-attempt.ts`: One rebase attempt: git's own rebase first, the implementer's session only when it stops or breaks the checks.
- `rebase-clean.ts`: A rebase git did alone: the branch already up to date, or rebased with no conflict, checked and pushed.
- `rebase-fetch.ts`: Brings the base branch and the pushed branch, as they are on GitHub now, into the container.
- `rebase-git.ts`: The git checks around a rebase: what a branch's history holds, what the agent left, and putting the branch back.
- `rebase-host.ts`: The host's own `git rebase` onto the base, tried before any agent: up to date, clean, or stopped.
- `rebase-prepare.ts`: The ticket's container put on its branch before a rebase, a simplification or a split, with the commit to restore.
- `rebase-publish.ts`: Checks the result, runs the project's checks, then pushes.
- `rebase.ts`: Rebases the ticket's branch onto its base, checks it and force-pushes it with a lease.
- `resync-branch.ts`: Puts the ticket's workspace on its branch as GitHub has it, after someone else pushed to it or rewrote it.
- `retarget-github.ts`: A change of target on GitHub: the base the pull request has now and the branches that exist.
- `retarget.ts`: Moves a finished ticket's own commits onto another base branch, then points its pull request at it.
